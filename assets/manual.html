1. The two safe tiers

(BL) Images only ever imports images under these licenses. Everything else is filtered out of search and re-checked on the server at import.

TierLicensesWhat it means
Safe anywherePublic domain, CC0, Public Domain Mark, U.S. government worksNo permission or credit legally required. We credit anyway (good faith, good practice).
Safe with creditCC BY 2.0 / 2.5 / 3.0 / 4.0Free for any use, including print and fundraising, as long as the credit travels with it. The plugin writes it everywhere automatically.
Owned / licensed to DPFYour own uploads and contributor licensesPhotos DPF took or was given permission to use. Never appears in search.

Always blocked: ShareAlike (BY-SA), NonCommercial (any NC), NoDerivatives (any ND), GFDL, "unknown", fair use. Flickr results are excluded by default because their licenses are self-declared by uploaders (Settings can turn them on, not recommended). Unsplash, Pexels and Pixabay aren't sources: their licenses aren't public-domain or CC BY, and their photos come with no model releases.

2. Finding & importing

  1. (BL) Images → Find & Import (or the "(BL) Images — find free images" tab inside any WordPress/Elementor image picker).
  2. Search. Results come from Openverse (Smithsonian, The Met, NASA, Library-of-Congress-era photos via rawpixel, Cleveland & Brooklyn museums, Europeana…) and Wikimedia Commons. Filter by tier, shape and kind.
  3. Click images to select them. In library means we already have it — click to use it.
  4. Optional: add context for Claude ("Folsom Prison, 1950s; for an article on wrongful convictions") — better alt text.
  5. Import. Each image goes through: download original → fingerprint → snapshot the source page → WebP → Claude writes alt text/title/description and checks for people → Media Library.
An amber People or Restrictions note on a result means Wikimedia flags personality rights, a trademark or an insignia. You can still import it for news-context use, but read Releases first.

3. Uploading your own

Find & Import → Upload your own. You'll be asked:

  • Right to use: DPF's own photo · the owner gave permission · public domain (with source URL) · CC BY (with source URL + version).
  • Creator (required), copyright holder, and for permission-based photos how permission was given or a linked contributor license.
  • People in the image, and any signed releases to link.
  • The responsibility statement: it's your responsibility to be sure DPF may use the image, and your name, account, IP address and the time are permanently recorded so you can be contacted about it.

4. What gets recorded (the "sleep well" part)

EvidenceWhy it matters
The source's own API response stating the license, saved at the moment of importProves what the source said the license was on that date, even if they change it later.
A snapshot of the source web pageSame, in human-readable form.
A Wayback Machine capture of the source pageAn independent third party's copy that DPF could not have altered.
The original file, kept in a private vault, with its SHA-256 fingerprint (and Wikimedia's own SHA-1 cross-check)Proves exactly which image we received. Also your full-resolution master for print.
The served WebP's fingerprintProves the file on the site is the one we recorded.
Rights metadata embedded in the file (IPTC/XMP: creator, credit, license, copyright notice)The credit travels with the file wherever it goes. Removing it can itself be a violation (17 U.S.C. §1202), so we put it back after conversion.
Who imported it, when (UTC to the microsecond), from which IPAccountability.
A hash-chained ledger entry, timestamped daily on the Bitcoin blockchain via OpenTimestampsEditing or deleting any past record breaks the chain, and Tools → Verify detects it. The daily timestamp proves the records existed, unaltered, on that date. Nobody, including DPF, can back-date them.

5. The Library & each image

Library searches title, alt text, creator, credit and Claude's keywords, with filters for Has issues · No provenance · People need a release · Not used anywhere · Not WebP · Missing alt text. WordPress's own Media Library search also matches alt text, credits and keywords now. Click an image to open its panel:

  • Focal point: click the subject. Every cropped slot (sliders, cards, banners) centers on it.
  • Metadata: title, alt, description, keywords, people status. Or Rewrite alt with Claude. Every change is recorded in the ledger. The caption/credit line is automatic.
  • Provenance & license: everything in section 4, Download evidence package (.zip), and Download full-resolution original (for print).
  • Releases: link signed releases, or request one for the people in this image.
  • Where it's used: every page, post, Elementor template and setting, with View / Edit in Elementor links.
  • Replace this image: swap the file but keep its ID, alt, title, caption, releases, focal point and every page that uses it. Same URL updates pages instantly (a visitor's browser may briefly show the old one). New URL avoids caching entirely by rewriting every reference. The old file is archived in the vault.
  • History: the image's ledger entries.

Images that were in the library before (BL) Images show "No provenance" with a form to record where they came from. If you don't know, consider replacing the image.

6. Releases: how it's done in real life

A free license covers the photo's copyright, not the person in it. Using someone's recognizable face alongside advocacy or fundraising can imply they endorse it. Professionals handle that three ways, and so does this plugin:

Photo & Likeness Release (model release)

For anyone featured: a speaker portrait, an honoree, an exoneree's story, a donor in an ad. Releases → New release, pick Photo & Likeness Release, enter name + email, link the image(s), then Email link (or Copy signing link to text it). They see the images and the release, can add limitations, type their legal name, draw a signature, consent to e-signing, review the exact final text, and sign. They get a signed copy by email. You get a notification plus a certificate in the vault. The linked images switch to Release on file.

Minors: tick "The person pictured is a minor". A parent or guardian signs and states their relationship.

Photo Contribution License

For people who give DPF photos (a volunteer photographer, a family, a partner). Their signing page lets them upload the photos. Each file's fingerprint is written into the license they sign, so the license covers exactly those files. Then import each photo from the release's panel. It arrives as Owned / licensed to DPF, credited "Photo courtesy of …".

Event Photography Notice (Awards Dinner, rallies, webinars)

Nobody collects 300 signatures at a gala. The accepted practice is notice: a line in the registration/ticket terms, a sign at the entrance, an announcement, plus a way to opt out (a colored sticker or lanyard). Create an Event Photography Notice record, tick how notice was given, attach a photo of the signage and a screenshot of the registration terms, and note any opt-outs. Link the event's photos to it. Tip: anyone you'll feature individually (an honoree's portrait on a fundraising mailer) should still sign a likeness release.

Paper releases

Create the release with method Paper, then Attach file with the scan or phone photo of the signed form. That marks it signed and fingerprints the scan.

Editorial / newsworthy

Historical and news photos of public events (a 1960s protest, a courthouse press conference) are generally usable in news and commentary context without releases. Mark them Editorial / newsworthy use only, and avoid using them in ads or fundraising appeals that could imply the people pictured endorse DPF.

Revocation

Releases are irrevocable, but the template promises DPF will honor a written request to stop new uses. Use Revoke (stop new uses). Linked images are flagged in the audit.

The release templates (Releases → Edit release templates) are solid plain-English starting points modeled on common nonprofit practice. Have DPF's counsel review them once. Every edit creates a new version, and signed releases keep the exact text their signer saw.

7. Credits & captions

  • Caption, the photo-desk credit line: Photo: Carol M. Highsmith / Library of Congress · Public domain or Photo: Jane Doe / Wikimedia Commons · CC BY 4.0.
  • Description, the full Creative Commons "TASL" attribution (Title, Author, Source, License, with links) plus the modification notice CC BY 4.0 requires ("Resized and converted to WebP by Death Penalty Focus").
  • Inside the file: IPTC/XMP creator, credit, copyright notice and license URL.
  • On hover: visitors see the credit when they point at a credited image (Settings → Front end).
  • Credits page: create a page containing [bl_image_credits] (or [bl_image_credits used="yes"] for only images in use). The hover credit links to it.
Using an image off the website (print, social, email, video)? Download the original from the image's panel and copy the Caption credit line alongside it. For CC BY, the credit must appear wherever the image does.

8. Tools

  • Usage index: build it once. It keeps itself current afterwards.
  • Duplicates: 1) Fingerprint images, 2) Find duplicates. Exact groups (identical files) are checked automatically; tick a Similar group only if it truly is the same picture, and change the keeper with its radio button if you like. 3) Consolidate all checked groups (or one group at a time): every reference moves to the keeper, the keeper is converted to WebP if it isn't already, and the other versions are deleted once nothing references them. Reference changes are undoable (Undo list); deleted versions are archived in the vault first.
  • Convert existing library to WebP: JPG/PNG/GIF become WebP, pages are updated, the old files stay on disk so outside links keep working. Build the usage index first.
  • Provenance ledger: Verify the whole ledger, Timestamp now, recent entries.
  • Undo reference changes: every re-point, replacement and conversion can be rolled back.

9. License Audit

A board-ready view of every image: provenance status, tier, license, people status, times used, issues. Export full audit (CSV) for your records. Two one-click fixers:

  • Adopt (BL) Slide Editor Wikimedia imports: brings older Slide Editor imports into the ledger, re-checks their license today, and flags any outside the safe tiers for replacement.
  • Write missing alt text with Claude: works across the whole library.

10. If a claim ever arrives

  1. Don't reply yet. Find the image (Library search, or the URL in the letter).
  2. Open it → Download evidence package. It contains the provenance certificate, the original file, the source's own license statement from the day we took it, the source-page snapshot, the Wayback link, linked signed releases, the served file, and the ledger with instructions for anyone to verify it independently.
  3. Tools → Verify the whole ledger and note the result.
  4. Send the package to DPF's counsel. Most "copyright troll" demands collapse on contact with a documented public-domain or CC license.
  5. If the claim has merit, use Where it's used to find every placement, and Replace the image site-wide in one step.

12. Setup & updates

  • Claude: uses the same Cloudflare Worker as (BL) Slide Editor (its describe mode). Leave Settings → Worker URL blank to borrow Slide Editor's settings. If Claude is unreachable, imports still complete using the source's own description, and the image is flagged for a people review.
  • Evidence vault: wp-content/uploads/bl-images-vault-…/, blocked from the web. Include it in UpdraftPlus backups (it's inside uploads, so it's included by default).
  • Updates: new versions ship via GitHub Releases. WordPress shows Update now on the Plugins page.
